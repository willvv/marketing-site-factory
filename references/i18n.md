# Bilingual sites (English + Spanish, or any pair)

Offered at intake. Choose with `new-site.mjs --langs <default>,<second>`; the first code is the
default and lives at the root, so its URLs are the canonical ones. Choose the default from the
**language of the market** (and of any existing indexed pages - changing it later moves every
URL).

## How the template does it

- `src/i18n/locales.ts` lists locales; `src/i18n/<code>.ts` is one dictionary per language,
  typed against `Dict` so a missing key is a **build error**, not an empty string in production.
- One route file (`src/pages/[...path].astro`) renders every page in every locale.
- URLs: default unprefixed (`/servicios/`), others `/<code>/...` (`/en/services/`).
- **Slugs are translated** (`/servicios/` and `/en/services/`), never `/en/servicios/` - a
  hybrid serves nobody and URLs are part of what engines read. Slugs live in each dictionary.
- The language is derived from the URL (`langFromPath`), so components never take it as a prop.

## SEO for two languages (all implemented; verify, don't re-invent)

- **hreflang**: every page lists itself and its translation (`<link rel="alternate"
  hreflang=...>`) plus `x-default` pointing at the default-language page. Pairs must be
  reciprocal - `check-site.mjs` confirms every target exists.
- `og:locale` + `og:locale:alternate`; `<html lang>` per page.
- `@astrojs/sitemap` is configured with the `i18n` option, so `sitemap-0.xml` carries
  `xhtml:link` alternates.
- Canonical points at the page's **own** URL in its own language (never at the other language).
- **Do not auto-redirect by `Accept-Language` or IP.** It hides one language from crawlers and
  traps users. Offer a visible switcher instead.
- The language switcher jumps to the **same page** in the other language, and falls back to that
  language's home, never a 404.
- `llms.txt` lists pages per language; write the business description in the default language
  and name the other.
- FAQ per language in `src/data/faq.ts`. **Write each in its language natively - do not
  machine-translate the questions**; people phrase searches differently per language.
- JSON-LD `inLanguage` lists both; `knowsLanguage` in `src/config.ts` -> `business`.

## Content

- Translate meaning and keywords for the market, not word-for-word; prices/units/phone formats
  per locale; addresses stay as they are.
- Brand names, product names and the business name are **not** translated.
- Both languages need every page - no half-translated site. If a language isn't ready, don't
  list it in `locales.ts`.
- WhatsApp greeting per language: `contact.whatsappMessage` in `src/config.ts`.

## Adding a language to an existing site

1. Copy `src/i18n/en.ts` to `<code>.ts`, translate everything including `slugs`, `htmlLang`,
   `ogLocale`.
2. Add it to `locales.ts` (import, `locales` array, `dictionaries`).
3. Add its FAQ list in `src/data/faq.ts` and per-language WhatsApp text in `config.ts`.
4. Add its sitemap locale mapping in `astro.config.mjs`.
5. `npm run build`, `check-site.mjs --strict`, then submit with IndexNow.

## Other writing systems

Right-to-left languages need `dir="rtl"` on `<html>` and mirrored layout: add `dir` to the
dictionary and set it in `BaseLayout.astro`. Pick fonts that cover the script and verify the
share card text renders correctly in the generated image.
