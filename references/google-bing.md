# Google Analytics, Search Console, Bing, IndexNow

## What is automated

| Task | Script | Needs |
| --- | --- | --- |
| Verify the base domain with Google (DNS TXT, via Cloudflare) | `register-site.mjs --verify-domain` | service account + Cloudflare token |
| Create the GA4 property and web data stream | `register-site.mjs <slug>` | SA is Administrator on the GA account |
| Write `ga4Id` into `src/config.ts` | `register-site.mjs <slug>` | (same) |
| Add the Search Console property + submit `sitemap-index.xml` | `register-site.mjs <slug>` | SA owns the domain |
| Submit URLs to Bing/Yandex/etc. | `indexnow.mjs <slug>` | key file deployed |
| Bing AddSite / SubmitUrlBatch | `bing.mjs` | Bing API key (**untested** - see below) |

Matched on natural keys (property name = hostname, stream URL, Search Console URL), so reruns
converge instead of duplicating.

## Facts that make it work unattended

- GA **accounts** cannot be created over the API - only properties. The user creates the
  account once and grants the service account Administrator in the UI (no API for the first
  grant). Free tier caps at 100 properties per account.
- Search Console **domain ownership cascades to every subdomain**: verify the base domain once
  and `site1.example.com`, `site2.example.com` ... are owned automatically. A *different* domain
  (a client's own) is a separate verification, or Search Console accepts the property and then
  rejects the sitemap with 403.
- The first verification attempt often fails while DNS propagates; the script retries.
- A `pages.dev` host cannot be verified by DNS - attach a real domain first.

## If the dashboard needs a human (drive Chrome or give the clicks)

Always give the exact URL. With the Claude in Chrome extension available, offer to do the
clicking in the user's signed-in browser; stop and hand over for passwords, 2FA or CAPTCHAs.

**Add a human owner to Search Console** (so the dashboard is visible in their account):
https://search.google.com/search-console -> Settings -> Users and permissions. (The API has no
user-management endpoint - alternatively `register-site.mjs` can add an owner through the Site
Verification API `webResource.update`.)

**See the GA4 data**: https://analytics.google.com/ -> pick the property named after the
hostname. Realtime report confirms the tag after deploy.

**Bing Webmaster Tools - the recommended one-time import**
1. Sign in at https://www.bing.com/webmasters (Microsoft account).
2. Add a site -> **Import** -> sign in with the Google account that owns the Search Console
   properties -> tick the sites -> Import. Imported sites are **verified automatically**, and
   Bing re-checks against the Google grant periodically (re-import if the Google access is
   revoked). Up to 100 sites per import; allow up to 48 h for traffic data.
3. Sitemaps carried over from Search Console; add `sitemap-index.xml` manually if missing.

**Bing API key** (optional; UI-only): Settings -> API access -> API Key -> Generate. One key per
user, usable across sites. Export `BING_API_KEY` or put `bingApiKey` in `credentials.json`.

> `bing.mjs` uses `https://ssl.bing.com/webmaster/api.svc/json/<Method>?apikey=...` with
> `AddSite`, `SubmitUrlBatch` (<= 500 URLs per call, 10,000/day) and `GetUserSites`. The shape is
> from Bing's published reference and a 2019 blog post; it has **not** been exercised against a
> live key by this skill. IndexNow + the import already cover indexing, so treat this as a
> bonus and read the HTTP status it prints.

## IndexNow

One random key per user (generated by `setup-cloudflare.mjs`, stored in `config.json`). Each
site hosts it at `https://<host>/<key>.txt` containing exactly the key (the scaffold writes the
file). Submissions go to `api.indexnow.org`; 200/202 = accepted. A rejected submission almost
always means the key file isn't deployed yet. Google ignores IndexNow.

Run after every deploy that changes content.

## Verification meta tags (fallback)

If DNS verification isn't possible for some reason, put the tag values in `src/config.ts` ->
`verification.google` / `verification.bing`; `SEO.astro` renders them only when set.

## Moving a site to its own domain later

GA4: patch the existing data stream's `defaultUri` (do **not** create a new stream - a new one
gets a new measurement id and splits history). Search Console: add the new domain, verify it
by DNS_TXT, submit its sitemap. See `domain-move.md`.
