# Findability - SEO, answer engines, indexing, analytics

Small businesses are found by searching or by asking an assistant. A beautiful site nobody can
find is a failed deliverable, so all of this ships with **every** site. The template already
implements the plumbing; your job is to fill it with true, specific content.
`scripts/check-site.mjs` verifies the mechanical parts.

## Classic SEO - the floor

- Unique `<title>` and `<meta name="description">` per page (description ~120-160 chars).
- `<link rel="canonical">` to that page's own production URL.
- Open Graph + Twitter Card on every page with a real **1200x630** `og:image`
  (model-generated - `imagery.md`). `og:image:width/height` are declared only for the default
  card, because a wrong pair is worse than none.
- Exactly one `<h1>` per page; headings descend without skipping levels.
- Descriptive `alt` on every image (empty `alt=""` for purely decorative); `width`/`height`
  set so nothing shifts.
- Correct `<html lang>`; generated `sitemap-index.xml`; `robots.txt` allowing crawl.
- **JSON-LD** (one `@graph` per page, only true facts - omit what is unknown):
  - the business entity: use the most specific `@type` that is true (`Restaurant`, `Dentist`,
    `LocalBusiness`, `ProfessionalService`, `TouristAttraction`...). Local businesses get a real
    `address`, `telephone`, `openingHours`; service businesses get `areaServed`.
  - `WebSite`, and `BreadcrumbList` on every page below the root.
  - `FAQPage` wherever the FAQ is shown.
- Internal links: every page reachable from the nav; related pages link to each other with
  descriptive anchor text.
- Performance is a ranking input: see Core Web Vitals in `brand-and-design.md`.

## Answer-engine optimisation - how the site gets quoted

ChatGPT, Gemini, Perplexity, Copilot and Google's AI answers quote pages that answer a question
directly, in self-contained prose, with the entity unambiguous.

- **Every site has a real FAQ** in `src/data/faq.ts`, rendered as visible text *and* emitted as
  `FAQPage` JSON-LD. It is not decoration - these are the questions the business is actually
  asked.
- **Write questions the way a customer would type them**, in the site's language:
  "How much does a small move cost in San Jose?", not "Our pricing".
- **Each answer stands alone.** An assistant lifts one paragraph out of context. No "as
  mentioned above".
- **Lead with the answer, then qualify.** Sentence one answers; the rest adds nuance.
- **Put the specifics in the answer**: town, price (only if supplied), capacity, hours, phone /
  WhatsApp. A quoted answer with no contact detail wins nothing.
- **Name the entity explicitly** in copy: full business name, town, region. Assistants
  disambiguate on those, and many small businesses share a name with something else.
- **Never fabricate an answer to make a nice FAQ.** If the price is unknown, "it depends on X -
  message us on WhatsApp" is a good, honest answer.
- Plain text answers (the same string goes into the JSON-LD).
- 6-12 questions is typical; group by intent (price, coverage, process, trust, logistics).

### `public/llms.txt`

A short plain-text summary for assistants that fetch it: who the business is, what it sells,
where, how to contact it, key pages. Keep it factual and current; it is regenerated by hand when
the business changes. One list of pages per language.

### Let the AI crawlers in

`robots.txt` explicitly allows `GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `Google-Extended`,
`PerplexityBot`, `ClaudeBot` (and `Applebot-Extended`), because a blanket allow is sometimes
read conservatively and being explicit documents the intent. If a client wants out of AI
training, change that block for that site and record it in `SITE.md`.

## Getting indexed

| Engine | How |
| --- | --- |
| Google | Search Console property + `sitemap-index.xml` submitted by `register-site.mjs` |
| Bing, Copilot, ChatGPT search, DuckDuckGo, Yandex, Naver | **IndexNow** (`indexnow.mjs`) + Bing Webmaster import (`google-bing.md`) |
| Everyone | an internal link from an already-indexed site (portfolio/hub page) is the cheapest discovery path - add one |

Verification meta tags for Google and Bing live in `src/config.ts` -> `verification`, empty by
default and rendered only when set (a domain-property verification by DNS makes them unnecessary).

IndexNow: each site hosts the user's key at `public/<key>.txt`; after any deploy that changes
content run `node <skill-dir>/scripts/indexnow.mjs <slug>`. Cloudflare's own "Crawler Hints"
toggle is dashboard-only and not settable over the API - don't chase it.

## Analytics - two layers, both through `src/config.ts` -> `analytics`

1. **Cloudflare Web Analytics** - free, cookie-less, no consent banner, token created by
   `provision-site.mjs` (`POST /accounts/{id}/rum/site_info`). The honest numbers (no
   ad-blocker gap).
2. **Google Analytics 4** - `ga4Id` is `null` until `register-site.mjs` writes the
   measurement id; the snippet renders nothing while null, so an unregistered site is never
   broken. Clients ask for it and it feeds Google's own tooling.

Both are skipped outside production builds so previews don't pollute the numbers. GA4 sets
cookies - if the audience is in a jurisdiction that needs consent, add a consent mechanism or
ship Cloudflare-only and tell the client why.

## Pre-launch SEO checklist

- [ ] `check-site.mjs --strict` is clean
- [ ] Titles/descriptions unique and written, not template text
- [ ] FAQ real, per language, answers standalone with contact detail
- [ ] `llms.txt` and `robots.txt` correct, sitemap reachable on the production domain
- [ ] `og-default.png` viewed with eyes: spelling, logo, crop
- [ ] GA4 id committed and deployed; Search Console shows the sitemap as "Success"
- [ ] IndexNow submitted; Bing import done
