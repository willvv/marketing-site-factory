# marketing-site-factory

A [Claude Code](https://claude.com/claude-code) skill that turns **one business idea into a live,
indexed, analytics-wired marketing website** on infrastructure *you* own: your GitHub, your
Cloudflare, your Google and your ChatGPT accounts.

You say *"Create a website for Acme Plumbing: emergency plumbing in Cuenca, Spanish and English."*
Claude does the rest, in a fixed order, to a fixed standard.

> **Status:** works end to end on its author's accounts for the parts listed under
> [What is and is not verified](#what-is-and-is-not-verified). It is opinionated on purpose: the
> value is in the decisions already made. If you disagree with one, fork it and change it
> ([Customising](#customising)).

## What you get

For every business you give it, the skill produces:

| Area | Result |
| --- | --- |
| **Code** | A **private** GitHub repo containing an [Astro](https://astro.build) static site (Tailwind CSS v4, TypeScript strict, minimal JS). |
| **Hosting** | A Cloudflare **Pages** project connected to that repo through Cloudflare's own Git integration: *push to `main` and it deploys*. No GitHub Actions. A Cloudflare **Worker** only if the site needs server-side work. |
| **Domain and email** | `<slug>.<your-domain>` with DNS, an HTTPS custom domain, and `info@<slug>.<your-domain>` forwarding to your inbox. |
| **Brand** | `BRAND.md` written *before* any page: positioning, palette with verified contrast, type pairing, voice, image direction and the exact image prompts. |
| **Imagery** | Every image and every icon generated by the image model through the `chatgpt-imagegen` skill, from a committed prompt manifest. No emoji, no stock icon fonts. |
| **Design** | A UI that follows the [`apple-design`](https://github.com/emilkowalski/skills) principles (direct response, interruptible motion, restraint, optical type), verified on desktop **and** mobile. |
| **Search** | Unique titles/descriptions, canonical URLs, Open Graph + Twitter cards, JSON-LD (business entity, WebSite, BreadcrumbList, FAQPage), `sitemap-index.xml`, `robots.txt`. |
| **AI assistants** | A real customer-voice FAQ written to be quoted, an `llms.txt`, and `robots.txt` that explicitly allows the AI crawlers. |
| **Analytics** | Cloudflare Web Analytics (cookie-less) **and** Google Analytics 4. |
| **Indexing** | A Google Search Console property with the sitemap submitted, IndexNow submission (Bing, Copilot, ChatGPT search, DuckDuckGo, Yandex) and a Bing Webmaster import. |
| **Languages** | Optional bilingual build (English/Spanish or any pair): translated slugs, `hreflang`, a language switcher that lands on the *same* page. |
| **QA** | `check-site.mjs` fails the build of a site that has duplicate titles, missing alt text, emoji, a wrong-size share card, leftover `TODO`s, and more. |
| **Records** | `SITE.md`: page inventory, every business fact and where it came from, infrastructure ids, what is still placeholder, a changelog. |

## How it works

```
 first run (once per machine)
 ┌──────────────────────────────────────────────────────────────────────────┐
 │ doctor ─► gh login ─► Cloudflare Global Key ─► scoped token (key dropped) │
 │        ─► Pages GitHub App ─► image skill + codex login ─► apple-design   │
 │        ─► Google service account ─► Chrome extension                      │
 └──────────────────────────────────────────────────────────────────────────┘
 per site
 intake ─► provision ─► scaffold ─► BRAND.md ─► generate images ─► build pages
        (repo, Pages,    (Astro     (before     (logo, hero,      (feature branches,
         DNS, email,     template)   any code)   icons, OG)        --no-ff to main)
         analytics)
        ─► register with Google ─► check-site --strict ─► deploy ─► IndexNow + Bing import
           (GA4 + Search Console)                                    ─► SITE.md + report
```

Claude reads [`SKILL.md`](SKILL.md) (the orchestrator) and loads the files in
[`references/`](references) only when a step needs them. The `scripts/` are plain Node 18+ with
**no npm dependencies**, so they run on Windows, macOS and Linux without an install step.

Every provisioning script is **idempotent**: it looks for the existing resource first, so
re-running after a partial failure is the intended recovery path.

## Install and first run

```bash
# Recommended: straight from this repository
npx skills add willvv/marketing-site-factory -g

# or clone it into your skills folder
git clone https://github.com/willvv/marketing-site-factory ~/.claude/skills/marketing-site-factory
```

Restart Claude Code so it discovers the skill, open it in an **empty folder** (that becomes your
workspace) and say:

> Set up marketing-site-factory for me.

Claude runs `scripts/doctor.mjs`, which is read-only and prints, for every missing prerequisite,
the exact fix and link. It then walks you through them in order
([`references/onboarding.md`](references/onboarding.md) has the full list):

1. GitHub CLI installed and `gh auth login`.
2. Cloudflare account with a domain on it. You run `setup-cloudflare.mjs` **in your own
   terminal**; it asks for your Global API Key (hidden prompt), mints a scoped token with
   only the permissions the scripts need, smoke-tests it, and discards the key.
3. The Cloudflare Pages GitHub App, one click: <https://github.com/apps/cloudflare-workers-and-pages/installations/new>.
4. The `chatgpt-imagegen` skill and `codex login` (ChatGPT sign-in).
5. The `apple-design` skill (downloaded from its upstream) and, optionally, the `ui-ux-pro-max` plugin.
6. A Google service account, added once as Administrator in your Google Analytics account.
7. The [Claude in Chrome](https://claude.ai/chrome) extension, for dashboards that have no API.

Then, for every site:

> Create a website for *Acme Plumbing*: emergency plumbing in Cuenca. Spanish and English.

Without Claude Code you can still run any script by hand, for example
`node scripts/doctor.mjs`.

## The decisions it makes for you

These are choices, not laws of nature. Each has a reason; each can be changed by forking.

| Decision | Why |
| --- | --- |
| **Astro static output**, not a SPA or SSR | These are top-of-funnel pages: fast, crawlable, cheap, nothing to patch. Anything that needs a server is a small Worker beside the site. |
| **Cloudflare Pages Git integration, never GitHub Actions** | Cloudflare authenticates the deploy itself, so no deploy credential ever sits in the repo, and there is no workflow to maintain. |
| **Every site is its own private repo** | Independent history, dependencies and deploys; a client can be handed theirs without exposing the rest. |
| **Feature branches, `--no-ff` merge to `main`** | `main` deploys on every push, so it must always build. |
| **One scoped Cloudflare token, Global Key discarded** | The Global Key can do everything on your account; the token can do only what this skill needs. |
| **Subdomain first, own domain later** | Sites are usually pitched before they are sold. A subdomain costs nothing and nothing in the code hard-codes it (it all comes from `src/config.ts`). |
| **WhatsApp is the primary call to action, email secondary** | The assumed market (Latin American small businesses) contacts businesses on WhatsApp. Switch with `primaryCta` in `config.ts`. |
| **Brand before code** | Palette, type, voice and image direction are what stop every site looking alike. |
| **Every site must look different** | The factory is the process, not the look: different palette, type pairing, layout logic and section rhythm per business. The Apple principles are applied as *principles*, never as Apple's look. |
| **Every image is model-generated; none is composed in code** | Text and logo included. Fixing a wrong word is done by prompting (quote the text, pass the real logo as a reference), not by overlaying HTML. Only a mechanical crop to 1200×630 or favicon sizes is allowed. |
| **Icons are a generated set, never emoji** | One shared style sentence, a transparent background, the brand palette. Emoji as icons is the clearest tell of an AI-made site. Only tiny functional glyphs (menu, close, chevron) are CSS/inline SVG in `currentColor`. |
| **FAQ is mandatory and written to be quoted** | Assistants lift a paragraph out of context: questions are phrased as customers type them, each answer stands alone, leads with the answer and names the business, town and contact. |
| **AI crawlers explicitly allowed** | GPTBot, OAI-SearchBot, ChatGPT-User, Google-Extended, PerplexityBot, ClaudeBot and Applebot-Extended. Being explicit documents intent. A client can opt out; record it in `SITE.md`. |
| **Cloudflare Web Analytics *and* GA4** | Cloudflare's numbers are cookie-less and honest; GA4 feeds Google's own tooling and clients ask for it. |
| **IndexNow plus a Bing import**, not a Bing API integration | IndexNow reaches Bing, Copilot, ChatGPT search, DuckDuckGo and Yandex. Bing's API key is UI-only and its verification is most reliably done by importing from Search Console. |
| **Bilingual: default language unprefixed, translated slugs, no auto-redirect** | The default language's URLs are the canonical ones; `/servicios/` and `/en/services/`, never `/en/servicios/`; redirecting by `Accept-Language` or IP breaks crawlers and sharing. |
| **Both languages complete, or not shipped** | A half-translated site is worse than a single-language one. Business names are never translated. |
| **Desktop and mobile are both verified with screenshots** | At 375, 768 and 1440 px: no horizontal scroll, tap targets ≥ 44 px, CTA visible on a phone without scrolling. |
| **No dependencies in the tooling** | One `node script.mjs` with nothing to install, on any OS. |
| **Per-user state outside every repo** | `~/.marketing-site-factory/` (override with `MSF_HOME`). Nothing personal is committed to a site. |

## The assumptions it makes

If one of these is wrong for you, the corresponding step will need adjusting.

- **You operate in a market where WhatsApp is the main channel** and (by default) Spanish is a
  likely language. The copy defaults and `primaryCta` assume this; both are config.
- **The business is small and local or service-based**: a handful of pages, a FAQ, a contact
  channel. It is not an e-commerce, booking or app platform.
- **All your sites share one Cloudflare zone** as subdomains of one base domain, on one
  Cloudflare account. Cloudflare's `pages.dev` namespace is global, so the script reads the
  project's real `subdomain` back instead of assuming `<slug>.pages.dev`.
- **Your Cloudflare login may own several accounts.** The account is chosen from the base
  domain's zone owner, never the first account in the list.
- **One GA4 account holds all the properties** (one property per site; the free tier caps this
  at 100). New properties are created with the time zone and currency you set in
  `setup-google.mjs detect`; the defaults are `America/New_York` and `USD`.
- **A Google service account is the automation identity** for GA4 and Search Console. GA
  *accounts* cannot be created by API, and the first access grant has no API either, so one UI
  step is unavoidable.
- **Domain verification is by DNS TXT, written through Cloudflare.** Ownership of the base domain
  cascades to its subdomains; a different domain needs its own verification.
- **Contact email is forwarded, not hosted.** `info@<site-host>` forwards to the address you
  configure (Cloudflare Email Routing). The destination must be verified once by clicking the
  link Cloudflare emails to it, which is the one unavoidable manual step.
- **The image model is reached through your ChatGPT sign-in** (`codex login`) via the
  `chatgpt-imagegen` CLI, about 20–60 s per image, generated serially.
- **You are not asking it to invent facts.** Anything it cannot know stays `null`, "no
  publicado" or a flagged `TODO`.
- **The Claude in Chrome extension is available** for the few dashboards without an API. If it is
  not, the skill gives you the exact link and clicks instead.

## The information it uses, stores and sends

### What you give it

| Input | Used for |
| --- | --- |
| Business name and a line about it | slug, copy, brand direction |
| Languages | which i18n build to scaffold |
| Real business facts you supply: WhatsApp, phone, address, hours, socials, logo, photos | `src/config.ts`, JSON-LD, the contact table in `SITE.md` |
| Your GitHub login (via `gh`) | repo owner |
| Your Cloudflare email and Global API Key (typed once, hidden) | minting the scoped token; **not stored** |
| Your base domain and forward-to email | DNS, custom domain, `info@` routing |
| Your Google Cloud project and GA account | the service account and where GA4 properties are created |

### What it stores, and where

Everything personal lives in **`~/.marketing-site-factory/`**, outside any repo:

| File | Contents | Sensitive |
| --- | --- | --- |
| `config.json` | GitHub owner, Cloudflare account id, base domain, forward email, IndexNow key, GA account, time zone, currency, image CLI path | no |
| `credentials.json` | the **scoped** Cloudflare token (and, only if you pass `--keep-global-key`, the Global Key; optionally a Bing API key) | **yes**, written mode `0600` |
| `google-service-account.json` | the Google service account key | **yes** |
| `sites.json` | registry of sites: repo, Pages project, host, Web Analytics token, GA4 and Search Console ids | no |

Environment variables (`CF_API_TOKEN`, `GITHUB_OWNER`, `BASE_DOMAIN`, `GOOGLE_SA_KEY`,
`BING_API_KEY`, ...) override the files.

**Inside a site's repo** the only identifiers committed are public ones: the GA4 measurement id,
the Cloudflare Web Analytics token (both are visible in any page's HTML) and the public IndexNow
key file. No credential ever goes into a repo; `scripts/package.mjs` and the guidance in
`SKILL.md` enforce it.

### The Cloudflare token's permissions

Minted by `setup-cloudflare.mjs`, nothing broader:

| Scope | Permission groups |
| --- | --- |
| Account | Account Settings Read, Pages Write, Workers Scripts Write, D1 Write, Email Routing Addresses Read/Write |
| Zone (your base domain) | Zone Read, DNS Write, Email Routing Rules Write, Workers Routes Write, Dynamic URL Redirects Write, Zone Settings Read |
| User | User Details Read, Memberships Read |

The token is restricted to the account and zone you name. Revoke it any time at
<https://dash.cloudflare.com/profile/api-tokens>.

### Who it talks to

| Service | What is sent | Why |
| --- | --- | --- |
| **GitHub** (via `gh`) | repo creation, pushes | the site's source |
| **Cloudflare API** | Pages, DNS, Email Routing, Web Analytics, zone rules | hosting and plumbing |
| **Google APIs** (Analytics Admin, Search Console, Site Verification) | property and stream names, site URLs, sitemap URL, a DNS TXT token | analytics and search registration |
| **OpenAI / ChatGPT** (via `codex` and `chatgpt-imagegen`) | **your image prompts and any reference images (such as the client's logo)** | generating imagery |
| **Bing / IndexNow** | your site's public URLs and the public IndexNow key | indexing |
| **raw.githubusercontent.com** | a one-off download of the `apple-design` skill | onboarding |

Nothing is sent to the author of this skill. There is no telemetry.

Be aware that **client logos and brand text go to the image provider** as references. If a client
cannot allow that, do not use `refs` for that site and say so in its `SITE.md`.

## Guardrails

- **No invented facts.** No fake testimonials, review counts, star ratings, "trusted by N",
  team members, statistics or press. Prices, phones, addresses and hours come only from you or a
  verified public source recorded in `SITE.md`. A real logo is used as-is, never redrawn.
- **Secrets never enter the chat.** The Global Key is typed into your own terminal. You can run
  any command inside a Claude Code session with the `!` prefix.
- **Spending money is never automatic.** Domain registration is documented with the price rules
  (quote the first-year *and* renewal price, get a yes, note that auto-renew is off by default)
  but no script buys anything.
- **The scripts that change things have `--dry-run`**, and the destructive path of each is
  guarded by an idempotency check.
- **Nothing is committed or pushed on your behalf** except to the site repos the skill created
  for that site.
- **`check-site.mjs --strict` must be clean** before a site is declared done.

## What is and is not verified

**Exercised against live accounts**

- Cloudflare token minting, including the smoke tests (zone, Pages, Email Routing, Web Analytics),
  and revoking the test token afterwards.
- Choosing the right account when a login owns several.
- `provision-site.mjs` in `--dry-run` against a real account, for a new and an existing slug.
- The GA4 and Search Console read paths, `register-site.mjs --dry-run` and `--add-owner --dry-run`.
- The template building as a single-language site (6 pages) and a bilingual one (11 pages) with
  translated routes and a sitemap with `hreflang`.
- `check-site.mjs`: it fails an unfinished site and passes a completed one.

**Written but not yet exercised live. Treat the first run as a test and read what it prints.**

- `bing.mjs` (Bing Webmaster API: `AddSite`, `SubmitUrlBatch`). IndexNow plus the Search Console
  import cover indexing without it.
- `setup-google.mjs gcloud` on a clean Google Cloud project.
- `provision-site.mjs` *creating* a brand-new repo and Pages project end to end on a fresh account.
- `register-site.mjs --add-owner` (only its read side and `--dry-run` were run).

**Known limits**

- No automated domain-move script is shipped; [`references/domain-move.md`](references/domain-move.md)
  documents the procedure and its traps.
- Cloudflare's Pages GitHub App install cannot be checked by machine; the doctor can only link to it.
- Image generation depends on a third-party sign-in path (`codex login`) that may change.
- Cloudflare Crawler Hints cannot be toggled by API; it is dashboard-only.

## Script reference

| Script | Does | Changes things? |
| --- | --- | --- |
| `doctor.mjs` | reports every prerequisite and its fix | no |
| `setup-cloudflare.mjs` | Global Key → scoped token; saves config; creates the IndexNow key | creates a token |
| `setup-google.mjs` `gcloud` / `detect` / `status` | service account + key; finds your GA account | creates a service account (`gcloud`) |
| `install-skills.mjs` | installs apple-design and chatgpt-imagegen | installs skills |
| `provision-site.mjs <slug>` | repo, Pages, DNS, custom domain, email, Web Analytics | yes, idempotent, `--dry-run` |
| `new-site.mjs <slug> --name ... --langs es,en` | scaffolds the template | writes a folder |
| `gen-images.mjs <manifest>` | generates every image in `images.json` | writes images |
| `register-site.mjs <slug>` | GA4 property + stream, Search Console + sitemap; writes `config.ts` | yes, idempotent, `--dry-run` |
| `indexnow.mjs <slug>` | submits the sitemap URLs | sends URLs |
| `bing.mjs` | Bing Webmaster `add` / `submit` / `sites` (**untested live**) | yes |
| `check-site.mjs <dir> --strict` | static QA of a built site | no |
| `package.mjs` | builds a shareable zip, refuses if it finds a secret | writes `dist/` |

## Customising

Fork the repository and change the bits that encode a decision:

- **Your market or language**: `assets/template/src/i18n/` and `config.ts` (`primaryCta`,
  `whatsappMessage`).
- **The look**: `references/brand-and-design.md` (the uniqueness rule and the design inputs).
- **The image style rules**: `references/imagery.md`.
- **The crawlers allowed**: `assets/template/public/robots.txt`.
- **What counts as an error**: `scripts/check-site.mjs`.
- **A different design skill**: change the name `doctor.mjs`/`install-skills.mjs` look for and
  the "Design" section of `SKILL.md`.

If you change a rule in `SKILL.md`, change the matching file in `references/` in the same commit;
the two drifting apart is the failure mode.

State directory: `MSF_HOME=/some/dir node scripts/doctor.mjs` runs everything against a throwaway
configuration, which is how this skill was tested.

### Sharing a private build

```bash
node scripts/package.mjs      # -> dist/marketing-site-factory.zip
```

Unzip into `~/.claude/skills/` on the other machine (PowerShell:
`Expand-Archive marketing-site-factory.zip -DestinationPath $HOME\.claude\skills`) and restart
Claude Code.
